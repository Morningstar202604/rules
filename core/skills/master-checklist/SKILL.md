# Master Checklist — 工程任务参考清单

一组可按需取用的自查项：诚实、验证、安全边界，以及按任务类型的检查清单。它是参考，不是必须逐条执行的流程；按任务规模与风险自行裁剪。

## 0. 怎么用

1. 按任务类型取用相关章节；小任务可以直接做，不必先声明会用到哪一节。
2. 交付前如需要，可过一遍 §6 自查。
3. 与其他环境指令（AGENTS.md 等）同时生效；冲突时以 AGENTS.md 为准。
4. 不适用或不需要的条目可以跳过，不必解释。

## 1. 建议基线（按需采用）

输出与诚实
1. 直接给结果：无前言、无客套、无 emoji；代码引 `文件:行号`；不写未要求的注释。
2. 没跑过的不说跑过；不确定就写「不确定」+ 验证方法；结论可溯源（文件 / 命令输出 / 文档）。
3. 交付时可视需要说明：改了什么 / 没动什么 / 什么未验证（含原因）。

修改与验证
4. 改前先读相关代码与既有约定；跟随现有风格；最小改动，不顺手重构、不引入新依赖。
5. 真跑验证才算完：聚焦测试 → 全量测试 → lint/类型 → 项目自带门禁；跑不了就明说。
6. 假绿灯是头号敌人：fail-closed 优先；「没跑」≠「通过」；被 `|| true` / `2>/dev/null` / 宽 except 吞掉的失败必须显式报告。

安全与边界
7. 密钥不进代码 / 日志 / 提交；凭据只从本机凭据库读，永不回显密钥值。
8. 破坏性操作默认直接执行，但先铺可回滚路径（备份 / 快照 / 隔离目录 / 分支 / dry-run），并在交付里说明风险与回滚方式。
9. Git：自主提交与推送；每完成一个可交付切片即提交，推送前确认目标是本人仓库。用户当轮明确说「先别提交」时以用户指令为准。

工程纪律
10. 改代码前可参考 `aqg-code-construction` 六步；敏感面（鉴权 / 权限 / 加密 / 密钥 / 信任边界输入 / 数据模型 / CI 部署 / 安装完整性 / 不可逆操作 / 跨仓契约）建议加强审查，具体深度按风险判断。
11. Skill-first 可选：需要现成流程时可先查已装技能；不适配就直接做。
12. 派生 / 定时任务是冷启动：先把纪律与验收标准写进它的 prompt（优先给技能文件路径让它自己读）。
13. 能用成熟库就别手搓；能离线先做完；外部依赖优雅降级；新依赖先报包体 / 构建代价。
14. 效率：独立命令并行、候选批量验证、上下文只引关键行——但验证与证据不省。

## 2. 开工参考（按需取用）

以下为可选做法，按任务复杂度自行决定用多少。

- 先盘点再动手：可留意本环境可用的技能 / MCP（见 §9）/ 子代理类型 / 并行命令。
- 能真验证就不猜：查真实文档、跑测试、开浏览器看效果。
- 能并行就不串行：独立任务可考虑派子代理，自己留上下文做判断。
- 能一次做完就不挤牙膏：尽量一次交付完整结果，需要用户决策的除外。
- 沉淀：本轮发现的硬知识（坑、命令、修复）可写回对应技能 / 文档。

**自主性**：

- 能靠侦察 / 实验自己得到答案的直接做，不追问；需要选方向时自行拍板并记录依据。
- 何时停止、是否执行不可逆操作，按授权、风险与上下文判断。
- 范围外的问题：记录进交付说明，不顺手改。

**开工清单**：

- [ ] 需要时判定任务类型 → 参考 §3（改代码）/ §4（接手陌生项目）/ §5（跨平台）/ §6（交付）
- [ ] 可选：查一下相关技能或能力
- [ ] 动手修改前读涉及的文件与既有约定（审计场景可先跑自带检查）
- [ ] 需求有歧义或需选方向 → 自行判断，必要时给出假设并说明
- [ ] 按需决定是否使用 AQG 等流程

## 3. 改代码清单

- [ ] 回归先行：修 bug 先写能复现失败的测试（RED）；新功能先写契约测试；无测试框架时用最小复现脚本 / 可复现手工步骤替代，并标注验证强度
- [ ] 最小切片：只改必须改的；不顺手重构；不引入新依赖
- [ ] 写完即验：聚焦测试 → 全量测试 → lint/类型 → 项目自带门禁（doctor / gate / CI 脚本）
- [ ] 命中敏感面 → 标记 deep 并审计一次（一次逻辑改动最多审一次；琐碎非敏感改动不审）
- [ ] 自查 5 轴：正确性 / 可读性 / 架构 / 安全 / 性能
- [ ] 无假绿灯写法（见 §8）

## 4. 接手 / 审计陌生项目的参考步骤

可按需采用：

- [ ] 1. 先跑它自带的检查、测试、构建脚本，拿到事实基线
- [ ] 2. 记录基线数字（如 `25 failed / 28 passed`），输出存档到会话记录或临时文件
- [ ] 3. 失败逐个定性：环境解析问题 / 测试桩问题 / 真 bug / 其他（flaky、断言过时、依赖装不上等），每类给出证据，避免一句「环境问题」带过
- [ ] 4. 改前确认可回滚：记录 git status；无 VCS 时先初始化或备份
- [ ] 5. 定修复范围：问题分级（阻断 / 建议 / 提示），按需决定本次修到哪
- [ ] 6. 分类修复：测试桩修桩；真 bug 可走 TDD（先复现后修复）；修完复跑并与基线对照
- [ ] 7. 静默失败扫描：搜 `|| true`、`2>/dev/null`、宽 except、工具缺失假通过、`catch {}` 空块，判断是合理容错还是假绿灯
- [ ] 8. 文档-代码交叉核对：版本号 / 计数 / 幽灵路径 / 死链 / 过时清单 / CHANGELOG 缺口
- [ ] 9. 全量验证 + 基线对照；视需要说明改了 / 没动 / 未验证
- [ ] 10. 可选：把验证写进 CI

## 5. 跨平台陷阱清单（Windows 实测，写跨平台代码时逐条对照）

| 陷阱 | 症状 | 修法 |
|---|---|---|
| 裸名 `bash` | Python subprocess 命中 `System32\bash.exe`（WSL 启动器）而非 Git Bash | 显式绝对路径定位，排除 system32 |
| `python3` 无别名 | Windows 只有 `python` / `py`，脚本整体失败 | 按 `python3 → python → py` 逐个解析 |
| `os.symlink` | 无特权报 WinError 1314 | 回退为包装脚本（exec 真实命令），不硬链接/复制 MSYS 二进制（DLL 解析会失败） |
| 路径分隔符 | MSYS 不认反斜杠 | 传给 bash 的路径统一转正斜杠 `C:/...` |
| 编码 | 中文 Windows 区域编码（cp936）吞中文 / 报错 | 子进程显式 UTF-8 解码；机器读的 JSON 用 ASCII 安全转义 |
| 行尾 | 文本模式 stdout 把 `\n` 再转一次成 `\r\n`（CSV 默认 `\r\n` → 产出 `\r\r\n`） | 显式 `lineterminator="\n"`；仓库统一 `.gitattributes` |

## 6. 交付自查（参考）

- 结论先行（第一句就是「发生了什么 / 结论是什么」）
- 证据：真实命令 + 真实数字
- 视需要说明：改了 / 没动 / 未验证（含原因）
- 无 emoji、无客套、无前言；代码引用 `文件:行号`
- 不把「未验证」包装成「完成」

## 7. 提示词模板（可直接粘贴给 AI）

**7.1 开工**
```
按 master-checklist 参考执行。任务：<一句话描述>。
可按需盘点可用能力（技能/MCP/子代理），不必逐节声明。
```

**7.2 审计 / 接手项目**
```
参考 master-checklist §4 对 <路径或仓库> 做审计：
跑它自带的检查/测试 → 记录基线数字 → 失败逐个定性（环境/测试桩/真 bug）→ 按需修复 → 复验。
交付：基线对照 + 改了什么/没动/未验证，结论引用 文件:行号。
```

**7.3 修 bug**
```
参考 master-checklist §3 修复：<bug 描述与复现步骤>。
可先写复现测试，最小修复，跑过验证后说明结果。
```

**7.4 派生子任务 / 定时任务（冷启动）**
```
让子任务先读 <技能文件绝对路径>（本机为 <规则目录>/skills/master-checklist/SKILL.md）再执行；
无法读文件时，把关键约束贴进 prompt。
背景：<上下文>；交付物：<验收标准>。
```

**7.5 只审不改（代码评审）**
```
按 master-checklist 的诚实要求审 <范围>：只报告问题与证据（文件:行号），
不顺手修改；结论分级（阻断/建议/提示），并注明实际读过的文件。
```

**7.6 能力拉满（可选）**
```
参考 master-checklist。可先盘点并启用可用能力（技能 / MCP / 子代理 / 并行）。
任务：<描述>
```

## Failure Handling（§8）/ 常见问题参考

| 症状 / 红旗 | 根因 | 动作 |
|---|---|---|
| 想说「应该没问题」而不真跑验证 | 声称比验证便宜，模型倾向走捷径 | 停，立即真跑；跑不了则如实报「未验证 + 原因」 |
| 想说「环境问题 / 历史遗留」绕过失败 | 归类逃避，回避根因 | 停，逐个定性（环境解析 / 测试桩 / 真 bug），每类给证据 |
| 想顺手重构、加注释、加依赖 | 表达欲膨胀，超出任务边界 | 停，回到最小改动；重构与换依赖另行立项 |
| 想报「完成」但没跑过任何验证 | 把「写完了」误当「做完了」 | 停，改报「未验证 + 原因 + 验证方法」 |
| 交付里出现 emoji / 客套 / 前言 / 「大概已经」 | 惯性客套掩盖不确定性 | 删掉重写；不确定就直说不确定 |
| 想用 `\|\| true` / `2>/dev/null` / 宽 except 让报错安静 | 求绿心切，制造假绿灯 | 停，定性：容错还是假绿灯？安全路径建议 fail-closed |
| 想直接删/覆盖/推送省事 | 不可逆操作风险 | 优先用可回滚路径（备份 / 分支 / dry-run / 隔离目录）并说明；按授权与风险决定是否继续 |
| 刚装的 MCP / 技能想不起来用（闲置） | 没盘点，回到肌肉记忆 | 可回看 §2 与 §9 对照表 |

## 9. 环境与能力档案（安装后按现场填写；下面是通用占位，不绑定某一台机器）

**已装能力与使用时机（想不起来用 = 没装）**

| 能力 | 使用时机（参考） |
|---|---|
| 文档检索 MCP / context7（若已配置） | 要写某库 / 某 API 的调用前，先取真实文档；不凭记忆编 API |
| 浏览器 MCP（若已配置） | 网页 / 前端改动，真浏览器验证行为并截图 |
| 符号检索 MCP / serena（若已配置） | 大仓库找符号 / 引用 / 精确编辑，优于盲目 grep |
| 子代理 | 独立探索 / 调研 / 审查并行派发，保主上下文 |

**权限模式**：按当前工具实际配置执行（如 plan / build / edit / yolo / guarded / auto）。刹车靠本文件 §1 与 §8，不靠外部弹窗。

**安装纪律**：来源白名单（L1 官方 > L2 厂商 > L3 社区）、版本钉死（禁止 latest）、凭据零明文、装完必须做发现验证（能被列出 / 能真调用）才算装好。

**安装命令与落点速查**

| 类型 | 来源 | 安装命令 |
|---|---|---|
| 技能（流程类） | github.com/obra/superpowers | `npx skills@1.7.2 add obra/superpowers --skill <名>` |
| 技能（官方） | github.com/anthropics/skills | 克隆后把技能目录拷进用户的 skills 目录 |
| MCP | npm / PyPI 官方命名空间（元数据查 registry.modelcontextprotocol.io，只读，不做安全审计） | `npm i -g <pkg>@<ver>` 或 `uvx --from <pkg>==<ver>` |
| 编辑器插件 | 对应客户端 Settings → Plugin Management | UI 安装 / 启用 |

**各工具落点**：见仓库 `docs/PORTABILITY.md` 的落点表（ZCode `~/.zcode/`、Claude Code `~/.claude/`、opencode `~/.config/opencode/`、通用 `~/.agent-rules/`）。装完重启会话并确认技能 / 子代理被列出才算验证。
